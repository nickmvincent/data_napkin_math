# Contributing New Cards to Data Napkin Math

Note: put me in GitHub Wiki eventually!

This guide explains how to contribute new inputs and scenarios to the Data Napkin Math project. The project uses Markdown files with structured frontmatter that are compiled into a JSON data file for the web application.

## Overview

There are two types of contributions you can make:

1. **Inputs** - Variables that represent real-world values (e.g., AI company revenue, dataset sizes, wage rates)
2. **Scenarios** - Calculations that use inputs to answer "what if" questions

## Directory Structure

```
data/
├── inputs/              # Input variable definitions
│   ├── dataset_size/    # Organized by variable_type
│   ├── wage_data/
│   ├── yearly_revenue/
│   └── ...
└── scenarios/           # Scenario calculations
    ├── distributing-money/
    ├── paying-for-new-labour/
    └── ...
```

## Contributing Inputs

### Input Schema

Each input is a Markdown file in the `data/inputs/` directory with the following frontmatter:

```yaml
---
title: Human-readable name of the variable
value: 1000000               # The numerical value
scale: 1000000               # Scaling factor for display (e.g., 1000000 for millions)
display_units: millions of dollars  # Units shown to users
variable_name: unique_variable_identifier  # Must be unique across all inputs
variable_type: category_type  # Groups related variables (e.g., dataset_size, wage_data)
entity: specific_entity      # The entity this value relates to
units: raw_units            # Raw units (e.g., dollars, tokens, people)
source_url: https://example.com/source  # Where this value comes from
date_added: 2025-03-19      # Date in YYYY-MM-DD format
tags:                       # List of tags for categorization
  - tag1
  - tag2
---

# Title of the Variable

**Value:** [formatted value with display units]

## Description

Brief description of what this value represents.

## Key Assumption

Any assumptions made in determining this value.

## Source

- [Source URL](URL)
- Additional notes about the source
```

### Variable Naming Convention

Variable names follow the pattern: `{variable_type}__{entity}__{units}`

Examples:
- `yearly_revenue__openai__dollars`
- `dataset_size__llama3__tokens`
- `wage_data__phd__dollars_per_question`

### Common Variable Types

- `average_length` - Average sizes/lengths
- `conversion_rate` - Conversion factors between units
- `dataset_attribute` - Properties of datasets
- `dataset_size` - Total size of datasets
- `deal_group_size` - Number of people/entities in deals
- `deal_value` - Monetary value of deals
- `group_size` - Number of people in groups
- `target_metric` - Target/goal values
- `total_books` - Book counts
- `training_detail` - ML training parameters
- `wage_data` - Payment rates
- `yearly_revenue` - Annual revenue figures

### Example Input

```yaml
---
title: Revenue from AI (OpenAI)
value: 3490000000
scale: 1000000
display_units: millions of dollars
variable_name: yearly_revenue__openai__dollars
variable_type: yearly_revenue
entity: openai
units: dollars
source_url: https://www.bloomberg.com/news/articles/2024-06-12/openai-doubles-annualized-revenue-to-3-4-billion-information
date_added: 2025-03-19
tags:
  - yearly_revenue
  - openai
  - dollars
---

# Revenue from AI (OpenAI)

**Value:** 3,490 millions of dollars

## Description

Value generated by AI in dollars

## Key Assumption

Assuming all 2024 OpenAI revenue is from LLMs

## Source

- [Bloomberg Article](https://www.bloomberg.com/news/articles/2024-06-12/openai-doubles-annualized-revenue-to-3-4-billion-information)
- Business news coverage of OpenAI
```

## Contributing Scenarios

### Scenario Schema

Each scenario is a Markdown file in the `data/scenarios/` directory with the following frontmatter:

```yaml
---
title: Scenario title
description: Question with {variable_placeholders} that can be swapped
input_variables:           # List of variable_names used
  - variable_name_1
  - variable_name_2
calculation_type: operations  # Currently only "operations" is supported
operations: '[{"func": "operation", "args": ["{var1}", "{var2}"]}]'  # JSON operations
result_label: Label for Result  # What to call the result
result_units: units          # Units of the result
category: Category Name      # Category for filtering
date_added: 2025-03-19      # Date in YYYY-MM-DD format
tags:                       # Tags for categorization
  - calculation
  - category-slug
---

# Scenario Title

## Description

Expanded description with example values filled in.

## Inputs

- **Input 1 Name**: value with units
- **Input 2 Name**: value with units

## Calculation

Human-readable explanation of the calculation steps.

## Result

The [Result Label] is calculated in [units].

## Category

Category Name
```

### Operations Format

The `operations` field is a JSON array of operation objects. Each operation has:

- `func`: The operation type (`multiply`, `divide`, `add`, `subtract`, `power`)
- `args`: Array of arguments (variable references like `"{variable_name}"` or literal numbers)
- `name`: (Optional) Name to store intermediate result

#### Simple Operations

Single operation:
```json
[{"func": "divide", "args": ["{yearly_revenue__openai__dollars}", "{group_size__world__people}"]}]
```

#### Complex Operations

Multiple operations with intermediate results:
```json
[
  {
    "func": "multiply", 
    "args": ["{dataset_size__llama3__tokens}", "{training_detail__openai__words_per_token}"], 
    "name": "total_words"
  }, 
  {
    "func": "multiply", 
    "args": ["{total_words}", "{wage_data__generic_freelance_higher__dollars_per_word}"]
  }
]
```

### Variable Placeholders in Descriptions

Use `{variable_name}` in the description to create dropdown selectors that allow users to swap between related variables:

```yaml
description: If we distribute AI revenue (say, {yearly_revenue__openai__dollars}) to some group of people (say, {group_size__world__people}), how much will each person get?
```

The UI will automatically create dropdowns for variables of the same `variable_type`.

### Example Scenario

```yaml
---
title: Distributing AI Company Revenue Broadly
description: If we distribute AI revenue (say, {yearly_revenue__openai__dollars}) to some group of people (say, {group_size__world__people}), how much will each person get?
input_variables:
  - yearly_revenue__openai__dollars
  - group_size__world__people
calculation_type: operations
operations: '[{"func": "divide", "args": ["{yearly_revenue__openai__dollars}", "{group_size__world__people}"]}]'
result_label: Per Person Revenue
result_units: dollars
category: Distributing money
date_added: 2025-03-19
tags:
  - calculation
  - distributing-money
---

# Distributing AI Company Revenue Broadly

## Description

If we distribute AI revenue (say, 3,490 millions of dollars) to some group of people (say, 8.10 billions of people), how much will each person get?

## Inputs

- **Revenue from AI (OpenAI)**: 3,490 millions of dollars
- **Number of people on Earth**: 8.10 billions of people

## Calculation

- Divide: 3,490 millions of dollars ÷ 8.10 billions of people

## Result

The Per Person Revenue is calculated in dollars.

## Category

Distributing money
```

## Building and Testing

After adding or modifying files:

1. Install dependencies (if not already done):
   ```bash
   npm install
   ```

2. Build the data file:
   ```bash
   npm run build
   ```

3. Start the development server:
   ```bash
   npm run serve
   ```

4. Open `http://localhost:8000` to test your changes

## Best Practices

1. **Use Existing Variable Types**: Check existing inputs to see if your variable fits an existing `variable_type`
2. **Provide Sources**: Always include source URLs and explain any assumptions
3. **Be Precise with Units**: Clearly distinguish between raw units and display units
4. **Test Calculations**: Verify your scenarios produce reasonable results
5. **Use Descriptive Names**: Make variable names self-documenting
6. **Include Context**: Add description and key assumptions to help others understand the values

## Common Issues

1. **Variable not found**: Ensure the `variable_name` in scenarios exactly matches the input definition
2. **Build errors**: Check that YAML frontmatter is properly formatted (proper indentation, quotes around strings with special characters)
3. **Display issues**: Remember that `scale` affects how values are displayed (e.g., scale of 1000000 shows values in millions)

## Contributing via GitHub

1. Fork the repository
2. Create a new branch for your changes
3. Add your Markdown files following the schemas above
4. Run `npm run build` to ensure everything compiles
5. Test locally with `npm run serve`
6. Submit a Pull Request with a clear description of your additions
